# เชื่อม ZKTeco MB10-VL กับ Chumkosoft

เครื่องส่งบันทึก ADMS ไปยังตัวรับบนเครือข่ายโรงเรียน ตัวรับตรวจ IP ต้นทางและส่งต่อเข้า Chumkosoft พร้อมรหัสลับ ระบบรับเฉพาะการเช็กเข้าที่เครื่องระบุว่าใช้ใบหน้า และใช้กฎเดิมเรื่องความยินยอม ภาคเรียน และเวลาเข้าโรงเรียน ผู้เรียนที่ใช้ลายนิ้วมือหรือเช็กออกจะไม่ถูกบันทึกเป็นการเช็กเข้าด้วยใบหน้า

## เตรียม Chumkosoft

1. เตรียมบัญชี KIOSK ที่เปิดใช้งานและรายการเครื่องสแกนของ MB10-VL ในฐานข้อมูล `ScannerDevice` ใช้ UUID ของเครื่องจากทะเบียนระบบเป็น `ZKTECO_ADMS_DEVICE_ID` หากยังไม่มี ให้แอดมินหรือผู้ดูแลฐานข้อมูลสร้างรายการเครื่องด้วยบัญชี KIOSK สำหรับจุดนี้ ก่อนเปิดตัวรับ
2. เพิ่มค่าต่อไปนี้ในไฟล์สภาพแวดล้อมของแอป เช่น `.env` ของ Compose บนเซิร์ฟเวอร์ และให้แอปโหลดค่าใหม่

   ```dotenv
   ZKTECO_ADMS_SECRET=<สุ่มด้วย openssl rand -hex 32>
   ZKTECO_ADMS_SERIAL=<เลขซีเรียลบนเครื่อง>
   ZKTECO_ADMS_DEVICE_ID=<UUID จาก ScannerDevice>
   ZKTECO_ADMS_PIN_MAP='{"001":"รหัสนักเรียนใน Chumkosoft"}'
   ```

3. PIN แต่ละตัวต้องตรงกับรหัสบนเครื่องทุกหลัก รวมเลขศูนย์นำหน้า และใช้รหัสนักเรียนจากระบบเป็นค่าในแผนที่ เริ่มด้วยผู้ใช้ทดสอบหนึ่งคน หลีกเลี่ยงการใช้ข้อมูลนักเรียนจริงในรอบตรวจการเชื่อมต่อครั้งแรก

## เปิดตัวรับบนเครือข่ายโรงเรียน

เตรียมไฟล์ `.env.zkteco-gateway` บน Mac หรือเซิร์ฟเวอร์ในเครือข่ายเดียวกัน เก็บไว้ภายนอก Git และให้เจ้าของไฟล์อ่านได้เท่านั้น

```dotenv
ZKTECO_ADMS_BIND_IP=<IP ของ Mac หรือเซิร์ฟเวอร์ที่เปิดตัวรับ>
ZKTECO_ADMS_SCANNER_IP=<IP ของ MB10-VL ควรจอง IP ที่เราเตอร์>
ZKTECO_ADMS_PORT=8088
ZKTECO_ADMS_SECRET=<ค่าเดียวกับฝั่งแอป>
ZKTECO_CHUMKOSOFT_ORIGIN=http://127.0.0.1:3000
```

ใช้ค่าตัวอย่างของ origin เมื่อรันตัวรับบนโฮสต์เดียวกับแอป หากรันบน Mac คนละเครื่อง ให้ใช้ HTTPS ของ Chumkosoft ใช้พอร์ตตัวรับเฉพาะภายในเครือข่ายโรงเรียน

```sh
node --env-file=.env.zkteco-gateway scripts/zkteco-adms-gateway.mjs
```

ใน **Cloud Server Setting** ของ MB10-VL ให้ตั้ง Server Address เป็น IP ของตัวรับ และ Server Port เป็น `8088` หรือพอร์ตที่กำหนด ตั้งเป็นโหมด IP และใช้ HTTP ภายในเครือข่าย ตั้งเวลาบนเครื่องให้ตรงกับเวลาไทย ตัวรับจะแสดงเฉพาะชนิดคำขอและสถานะ HTTP

## ตรวจผล

- `GET cdata → 200` หรือ `GET getrequest → 200` หมายถึงเครื่องติดต่อจนถึงตัวรับใน Chumkosoft ได้
- `POST cdata → 200` หมายถึงแอปประมวลผลบันทึกแล้ว ตรวจรายการเช็กเข้าและเวลาจริงใน Chumkosoft เพื่อยืนยัน
- `422` หมายถึงแอปยังไม่ตอบรับชุดข้อมูล ตรวจแผนที่ PIN เวลาเครื่อง การลงทะเบียน และความยินยอม ในกรณีที่ส่งชุดเดิมอีกครั้ง Chumkosoft ใช้รหัสเหตุการณ์เดิมป้องกันการบันทึกซ้ำ
- `503` ให้ตรวจค่าฝั่งแอปและสถานะบัญชี KIOSK ส่วน `502` ให้ตรวจว่าตัวรับติดต่อแอปได้

ตัวรับรองรับ ADMS แบบ ATTLOG ที่ส่งเป็นบรรทัดคั่นด้วยแท็บ โปรดทดสอบเครื่องจริงเพื่อยืนยันว่าเฟิร์มแวร์ส่งค่า check-in `0` และ face `15` ตามที่ส่วนเชื่อมนี้คาดไว้ รูปใบหน้า ลายนิ้วมือ และข้อมูลแม่แบบไม่ได้รับการร้องขอจากเครื่อง
