# เชื่อม ZKTeco MB10-VL กับ Chumkosoft

Chumkosoft รับบันทึกจาก MB10-VL ที่ API `/iclock/cdata` และ `/iclock/getrequest` บนเซิร์ฟเวอร์ ทดสอบ API บนเซิร์ฟเวอร์ได้ก่อน แล้วค่อยผูก `scanner.chumkosoft.com` ผ่าน Cloudflare Tunnel ของโรงเรียน ระบบตรวจ Serial ของเครื่องและใช้กฎเดิมเรื่องความยินยอม ภาคเรียน และเวลาเข้าโรงเรียน โดยนำเข้าเฉพาะการเช็กเข้าที่เครื่องระบุว่าใช้ใบหน้า.
## เตรียม Chumkosoft

1. เปิด **ระบบ → จุดสแกนใบหน้า → เครื่องสแกน ZKTeco** ด้วยบัญชีแอดมิน แล้วลงทะเบียนชื่อเครื่อง จุดติดตั้ง เลข Serial และบัญชีจุดสแกนที่เปิดใช้งาน หน้านี้แสดงสถานะการติดต่อและเวลาซิงก์ล่าสุดของแต่ละเครื่อง
2. หากติดตั้งด้วยค่าการเชื่อมต่อรุ่นเดิม เครื่องเดิมยังแสดงในหน้าจัดการ เปิด **แก้ไขเครื่อง** แล้วบันทึกเพื่อเก็บการลงทะเบียนไว้ในฐานข้อมูล

## ใช้รหัสนักเรียนอัตโนมัติ

ตอนลงทะเบียนผู้ใช้บนเครื่อง ให้ใช้รหัสนักเรียนใน Chumkosoft เป็น **User ID** โดยตัดขีดหนึ่งตัวออกและเก็บเลขศูนย์นำหน้าไว้ เช่น `68-0421` ใช้ `680421` ระบบค้นรหัสนักเรียนในฐานข้อมูลตอนรับบันทึกและใช้ผลที่พบเพียงคนเดียว หากพบหลายคน ให้กำหนดคู่รหัสจากหน้าเว็บก่อนใช้งาน

## จับคู่รหัสนักเรียนจากหน้าเว็บ

ใช้เมนูนี้เมื่อ User ID ที่ลงไว้บนเครื่องต่างจากรหัสนักเรียน คู่ที่ตั้งไว้มีผลก่อนการค้นจากรหัสนักเรียนอัตโนมัติ

เปิด **ระบบ → จุดสแกนใบหน้า → เครื่องสแกน ZKTeco → จับคู่รหัสนักเรียน** ด้วยบัญชีแอดมิน แล้วระบุ User ID บน MB10-VL กับรหัสนักเรียนใน Chumkosoft ให้ตรงทุกหลัก รวมเลขศูนย์นำหน้า คู่รหัสใหม่ใช้ได้ทันทีหลังบันทึก

นำเข้าได้สูงสุด 500 รายการต่อไฟล์ CSV UTF-8 โดยใช้หัวตารางและรูปแบบตามนี้

```csv
pin,studentCode
00421,69-0421
```

ตั้งคอลัมน์ `pin` เป็นข้อความก่อนกรอกใน Excel หากไฟล์มีรหัสซ้ำ รหัสนักเรียนที่หาไม่พบ หรือชนกับคู่รหัสของคนอื่น ระบบจะแจ้งข้อผิดพลาดและไม่บันทึกทั้งไฟล์ การเปลี่ยนนักเรียนของ PIN ที่มีอยู่ต้องยืนยันจากแบบฟอร์มทีละคน บันทึกสแกนที่เกิดก่อนการจับคู่ใหม่จะไม่ถูกนับให้นักเรียนในคู่ใหม่

หากเคยมี `ZKTECO_ADMS_PIN_MAP` ระบบจะแสดงคู่เดิมในตาราง ใช้ **ย้ายเข้าระบบ** เพื่อย้ายลงฐานข้อมูล หรือ **ยกเลิกการจับคู่** เพื่อปิดคู่เดิมได้จากหน้าเว็บ

## ตั้งค่าตัวรับบนเซิร์ฟเวอร์

สร้างค่าที่ใช้เฉพาะระหว่าง Tunnel กับแอปด้วยคำสั่ง `printf 'scanner-%s.internal\n' "$(openssl rand -hex 16)"` แล้วเก็บค่านั้นใน `.env` ของแอปพร้อม IP อินเทอร์เน็ตขาออกที่เครื่องใช้ ตัวอย่างนี้เป็นค่าจำลอง

```dotenv
ZKTECO_ADMS_TUNNEL_HOST=scanner-<เลขฐานสิบหก 32 ตัว>.internal
ZKTECO_ADMS_ALLOWED_IPS=<IP อินเทอร์เน็ตขาออกของโรงเรียน>
```

ระบุได้หลาย IP โดยคั่นด้วยจุลภาค แล้วให้แอปโหลด `.env` ใหม่ผ่านการ deploy ตามปกติ เก็บค่าของ `ZKTECO_ADMS_TUNNEL_HOST` ไว้กับผู้ดูแลแอปและ Tunnel คงการเข้าถึงแอปจากโฮสต์ไว้ที่ loopback ตาม Compose production

ก่อนผูกโดเมน ให้ลงทะเบียน Serial ทดสอบจากเว็บ แล้วรันคำสั่งนี้ที่เซิร์ฟเวอร์โดยแทนค่าตัวอย่างให้ตรงกับที่ตั้ง

```sh
curl --include \
  -H 'Host: <ค่า ZKTECO_ADMS_TUNNEL_HOST>' \
  -H 'CF-Connecting-IP: <IP โรงเรียนที่อนุญาต>' \
  'http://127.0.0.1:3000/iclock/getrequest?SN=<Serial ทดสอบ>'
```

`200 OK` พร้อมข้อความ `OK` ยืนยันว่า API รู้จักเครื่อง ส่วน `403` ให้ตรวจ Host, IP, Serial และสถานะรับบันทึก คำขอนี้จำลองการติดต่อเครื่องและอัปเดตเวลาติดต่อล่าสุดของเครื่องทดสอบ แต่ไม่บันทึกเวลาเข้าโรงเรียน

## ผูกโดเมนใน Cloudflare Tunnel

เมื่อทดสอบบนเซิร์ฟเวอร์ผ่านแล้ว เปิด **Cloudflare → Networking → Tunnels** แล้วเลือก Tunnel ที่ใช้กับ Chumkosoft เข้า **Routes → Add route → Published application** และใส่ค่า

| ช่อง | ค่า |
|---|---|
| Subdomain | `scanner` |
| Domain | `chumkosoft.com` |
| Path | `^/iclock/(cdata|getrequest)(\.aspx)?$` |
| Service | `http://app:3000` เมื่อ `cloudflared` อยู่ใน Compose network เดียวกัน ใช้ `http://127.0.0.1:3000` หาก Tunnel รันบนโฮสต์ |
| Additional application settings → HTTP settings → HTTP Host Header | ค่าเดียวกับ `ZKTECO_ADMS_TUNNEL_HOST` |

เพิ่มเป็น route แยกของ `scanner.chumkosoft.com` หากชื่อนี้ผูกกับ Worker แล้ว ให้ย้ายการผูกโดเมนมายัง Tunnel ก่อน ส่วน Worker ที่สร้างไว้สามารถเก็บไว้ได้ ตรวจว่า TLS ภายนอกใช้ HTTPS พอร์ต 443

### ตั้งค่าบน MB10-VL

1. ต่อเครื่องกับ Wi-Fi โรงเรียนและตั้งวันที่กับเวลาเป็นเวลาไทย
2. เปิด **Menu → COMM → Cloud Server Setting**
3. เปิด **Enable Domain Name** ใส่ **Server Address** เป็น `scanner.chumkosoft.com` เปิด **HTTPS** และตั้งพอร์ต `443` หากมีช่องแยก ใส่ชื่อโดเมนเปล่าในช่องที่อยู่
4. บันทึกแล้วกลับหน้าหลัก เปิด **ระบบ → จุดสแกนใบหน้า** บนเว็บแล้วกดรีเฟรช หากคำขอถึง Chumkosoft และตรวจ Serial ผ่าน จะเห็นสถานะ **ออนไลน์** และเวลาที่ติดต่อล่าสุด
5. ลงทะเบียนผู้ใช้ทดสอบบนเครื่องด้วย User ID ตามรหัสนักเรียน หรือใช้คู่รหัสที่ตั้งไว้ แล้วสแกนหนึ่งครั้งและตรวจเวลาเข้าโรงเรียนให้ตรงกับเวลาบนเครื่อง

### ตัวรับบนเครือข่ายภายใน

สำหรับช่องทางตัวรับเดิมผ่าน LAN ให้ตั้ง `ZKTECO_ADMS_SECRET` ฝั่งแอป แล้วเตรียมไฟล์ `.env.zkteco-gateway` บน Mac หรือเซิร์ฟเวอร์ในเครือข่ายเดียวกัน เก็บไว้ภายนอก Git และให้เจ้าของไฟล์อ่านได้เท่านั้น

```dotenv
ZKTECO_ADMS_BIND_IP=<IP ของ Mac หรือเซิร์ฟเวอร์ที่เปิดตัวรับ>
ZKTECO_ADMS_SCANNER_IP=<IP ของ MB10-VL ควรจอง IP ที่เราเตอร์>
ZKTECO_ADMS_PORT=8088
ZKTECO_ADMS_SECRET=<ค่าเดียวกับฝั่งแอป>
ZKTECO_CHUMKOSOFT_ORIGIN=http://127.0.0.1:3000
```

ใช้ค่าตัวอย่างของ origin เมื่อรันตัวรับบนโฮสต์เดียวกับแอป หากรันบน Mac คนละเครื่อง ให้ใช้ HTTPS ของ Chumkosoft ใช้พอร์ตตัวรับเฉพาะภายในเครือข่ายโรงเรียน

```sh
node --env-file=.env.zkteco-gateway scripts/zkteco-adms-gateway.mjs
```

ใน **Cloud Server Setting** ของ MB10-VL ให้ตั้ง Server Address เป็น IP ของตัวรับ และ Server Port เป็น `8088` หรือพอร์ตที่กำหนด ตั้งเป็นโหมด IP และใช้ HTTP ภายในเครือข่าย ตั้งเวลาบนเครื่องให้ตรงกับเวลาไทย ตัวรับจะแสดงเฉพาะชนิดคำขอและสถานะ HTTP

## ตรวจผล

- `GET cdata → 200` หรือ `GET getrequest → 200` หมายถึงเครื่องติดต่อจนถึงตัวรับใน Chumkosoft ได้
- `POST cdata → 200` หมายถึงแอปประมวลผลบันทึกแล้ว ตรวจรายการเช็กเข้าและเวลาจริงใน Chumkosoft เพื่อยืนยัน
- `422` หมายถึงแอปยังไม่ตอบรับชุดข้อมูล ตรวจ User ID บนเครื่อง รหัสนักเรียนหรือคู่รหัสบนเว็บ เวลาเครื่อง การลงทะเบียน และความยินยอม ในกรณีที่ส่งชุดเดิมอีกครั้ง Chumkosoft ใช้รหัสเหตุการณ์เดิมป้องกันการบันทึกซ้ำ
- `403` ให้ตรวจ IP อินเทอร์เน็ตขาออกของโรงเรียน เลข Serial และสถานะรับบันทึกของเครื่อง
- `503` ให้ตรวจ Secret และการตั้งค่าฝั่งแอป ส่วน `502` ให้ตรวจว่าตัวรับติดต่อแอปได้

ตัวรับรองรับ ADMS แบบ ATTLOG ที่ส่งเป็นบรรทัดคั่นด้วยแท็บ โปรดทดสอบเครื่องจริงเพื่อยืนยันว่าเฟิร์มแวร์ส่งค่า check-in `0` และ face `15` ตามที่ส่วนเชื่อมนี้คาดไว้ รูปใบหน้า ลายนิ้วมือ และข้อมูลแม่แบบไม่ได้รับการร้องขอจากเครื่อง
