# ตัวทดสอบสแกนหน้าแบบออฟไลน์ (Mac / Linux)

โปรแกรม Python นี้เป็น **แอปเดสก์ท็อปต้นแบบ** เปิดที่หน้าเชื่อมต่อ QR ก่อนและค้างอยู่ที่หน้านั้นจนกว่าจะจับคู่บัญชีจุดสแกนสำเร็จ จากนั้นเปิดหน้าสแกนและกล้องตามค่าที่ตั้งไว้โดยอัตโนมัติ แอปมี 5 หน้า: สแกนใบหน้า, ภาพรวม, ลงทะเบียนใบหน้า, เชื่อมต่อและซิงก์, และตั้งค่า ใช้ YuNet ตรวจใบหน้า, SFace สร้างค่าจดจำใบหน้า และ SQLite เก็บเช็กชื่อระหว่างไม่มีเน็ต **รายการเช็กชื่อยังส่งได้เฉพาะเซิร์ฟเวอร์จำลองในเครื่อง** จึงยังไม่ควรใช้ตัดสินการเช็กชื่อจริง

แอปติดตั้งบน Mac เป็น `.app` และบน Linux เป็นโปรแกรมพร้อมเมนูเปิดในระบบ **ไม่ต้องเปิด URL หรือเบราว์เซอร์** โฟลเดอร์ข้อมูลของแอปอยู่ที่ `~/Library/Application Support/Chumkosoft Scanner` บน Mac หรือ `~/.local/share/chumkosoft-scanner` บน Linux

เว็บสแกนผ่านเบราว์เซอร์ใช้ `@vladmandic/face-api` ส่วนแอปนี้ใช้ SFace: ค่าจดจำใบหน้าสองชนิด **ใช้ร่วมกันไม่ได้** API อัปโหลดใหม่บันทึกชนิดโมเดลไว้เพื่อแยกข้อมูล ไม่ต้อง export ฐานข้อมูลใบหน้าจริงมาใส่เครื่อง

## 1. เปิดแอปเดสก์ท็อปเพื่อทดลอง

ใช้ Python 3.9 ขึ้นไป ขณะพัฒนาในโฟลเดอร์ `offline_scanner`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python desktop_app.py
```

บน Mac ขณะ dev ให้เปิดผ่าน `./run-mac.command` (หรือดับเบิลคลิกไฟล์นี้) เพื่อใช้ Python ใน `.venv` และแสดงข้อความผิดพลาดใน Terminal หากแอปปิดตัว การรัน `python3 desktop_app.py` อาจใช้ Python คนละชุดกับที่ติดตั้ง PySide6 ไว้ อีกทางคือเปิด `dist/ChumkosoftScanner.app` ที่ build จากโค้ดล่าสุด

เมื่อเชื่อม QR สำเร็จ แอปจะเข้าหน้า **สแกนใบหน้า** และเปิดกล้องอัตโนมัติ แอปจะขอสิทธิ์กล้องกับ macOS/Linux ครั้งแรก หน้านี้แสดงภาพกล้องด้านซ้าย และนาฬิกา วันที่ จำนวนผู้สแกนวันนี้ ชื่อ รหัส และเวลาที่สแกนด้านขวา รายการใหม่ขึ้นทันทีหลังบันทึกใน SQLite และเปลี่ยนวันตามเวลาไทย หน้า **ลงทะเบียนใบหน้า** จะโหลดรายชื่อนักเรียนจากเว็บโดยอัตโนมัติ ให้เลือกนักเรียนแทนการกรอกรหัสหรือชื่อเอง แล้วกด **ลงทะเบียนจากภาพกล้อง** หรือ **เลือกรูปจากไฟล์** กล้องเปิดเองเมื่อเข้าหน้านี้และหยุดเมื่อไปหน้าที่ไม่ใช้กล้อง แอปเก็บภาพ JPEG ขนาดย่อใน SQLite ชั่วคราวจนเว็บตอบรับการอัปโหลด จากนั้นลบภาพในคิวในเครื่อง แต่ยังเก็บค่าจดจำใบหน้าไว้เพื่อสแกนออฟไลน์

หน้า **ตั้งค่า** เป็นที่เลือกกล้องเริ่มต้น (0–9) สำหรับทั้งหน้าสแกนและหน้าลงทะเบียน รวมถึงช่วงเวลาระหว่างการตรวจใบหน้า (0.5, 0.85 หรือ 1.5 วินาที) และช่วงพักก่อนตรวจคนเดิมซ้ำ (10, 30 หรือ 60 วินาที) ได้ หน้าสแกนแสดงหมายเลขกล้องที่ใช้อยู่โดยไม่มีตัวเลือกกล้อง ค่าจะบันทึกไว้ใน `settings.json` ของโฟลเดอร์ข้อมูลแอปบนเครื่องนี้เท่านั้น คำสั่ง `--camera` ใช้แทนค่าที่บันทึกสำหรับการเปิดครั้งนั้น วันเวลาเช็กชื่ออ่านจากนาฬิกาเครื่องและใช้เขตเวลา Asia/Bangkok; หากเวลาเครื่องคลาดเคลื่อนต้องแก้ที่ระบบปฏิบัติการ

แอปเชื่อม `https://chumkosoft.com` เป็นค่าเริ่มต้นและไม่บันทึกรหัสผ่านลงดิสก์ เว็บส่งเฉพาะชื่อ รหัส และห้องของนักเรียนที่ลงทะเบียนภาคเรียนปัจจุบันและยินยอมให้เก็บใบหน้า แล้วตรวจเงื่อนไขเหล่านี้ซ้ำตอนรับรูป ก่อนเก็บรูปใน RustFS และค่าจดจำแบบ SFace ใน PostgreSQL รายชื่อเก็บเฉพาะในหน่วยความจำขณะเปิดแอป จึงต้องเชื่อมเว็บเพื่อโหลดใหม่เมื่อเปิดแอปครั้งถัดไป หากเน็ตล่มหลังลงทะเบียน รูปจะรออยู่ในเครื่องและลองส่งใหม่เมื่อแอปยังเปิดและเชื่อมบัญชีอยู่ **API นี้ต้อง deploy พร้อม migration ก่อนจึงจะใช้งานจริงได้**

### เชื่อมบัญชีด้วย QR

เมื่อเปิดแอป หน้า QR จะแสดงเอง จากนั้นสแกน QR ด้วยมือถือ เปิดหน้าเว็บที่แสดง ตรวจรหัส 12 ตัวให้ตรงกับหน้าจอแอป แล้วเข้าสู่ระบบด้วย **บัญชีจุดสแกน (KIOSK)** เพื่อกดยืนยัน หากเบราว์เซอร์มีเซสชันบัญชีจุดสแกนอยู่แล้ว กดยืนยันได้ทันที แอปจะรับเซสชันและโหลดรายชื่อนักเรียนเอง QR มีอายุ 5 นาที ใช้ได้ครั้งเดียว และมีเพียงลิงก์ยืนยันกับรหัสตรวจสอบ ไม่มีรหัสผ่านหรือเซสชันใน QR ต้องมี Redis ของเว็บทำงานอยู่ หาก QR หมดอายุหรือเว็บติดต่อไม่ได้ แอปจะลองสร้าง QR ใหม่เอง ปุ่ม **สร้าง QR ใหม่** ใช้รีเฟรชด้วยตัวเองได้ แอปไม่มีช่องกรอกรหัสผ่าน

การทดสอบเว็บ dev ที่ `http://127.0.0.1:3000` ให้กด **เปิดลิงก์ยืนยันบน Mac** ในแอป เพราะ `localhost` บนมือถือชี้ไปที่มือถือเอง จึงสแกน QR เพื่อเปิดเว็บ dev จากมือถือไม่ได้ การเชื่อมกับเว็บจริงจะใช้ QR จากมือถือได้หลัง deploy API/หน้าเว็บและตั้งค่า HTTPS แล้ว หลังปิดแอปต้องเชื่อม QR ใหม่ครั้งถัดไป; ขณะเปิดแอปและเชื่อมแล้ว การสแกนใบหน้าใช้ข้อมูลในเครื่องต่อได้เมื่อเน็ตล่ม

เพื่อทดสอบกับเว็บ dev บน Mac ให้เปิดเว็บ Next.js ในเครื่องก่อน แล้วรันแอปจาก `offline_scanner` ด้วย:

```bash
./run-mac.command --site-url http://127.0.0.1:3000
```

แอปยอมรับ HTTP เฉพาะ `localhost` หรือ `127.0.0.1` ที่ระบุพอร์ตสำหรับ dev; เว็บจริงใช้ HTTPS เท่านั้น

เลือกกล้องเริ่มต้นในหน้า **ตั้งค่า** หรือกำหนดชั่วคราวด้วย `desktop_app.py --camera 1` โปรแกรมเปิดด้วยโมเดลที่ตรวจสอบแล้วในเครื่องทันที จากนั้นตรวจและดาวน์โหลดรุ่นใหม่เบื้องหลังโดยไม่หยุดหน้าต่าง หากมีรุ่นใหม่ ให้ปิดแล้วเปิดโปรแกรมอีกครั้งเพื่อใช้งาน การส่งข้อมูลไปเซิร์ฟเวอร์จำลองก็ทำเบื้องหลัง และหน้าต่างจะแสดงจำนวนรายการที่ยังรอส่ง

แอปมีโมเดลเริ่มต้นติดมาด้วย เมื่อติดตั้งครั้งแรกจะคัดลอกไปยังโฟลเดอร์ข้อมูลของผู้ใช้ แล้วตรวจรุ่นใหม่จาก `https://chumkosoft.com/models/scanner/manifest.json` ทุกครั้งที่เปิดแอป หากเว็บเข้าไม่ได้จะใช้รุ่นเดิมต่อ ดังนั้นการสแกนไม่ส่งภาพหรือคำขอไป Cloudflare ทุกเฟรม

### สร้างแอปติดตั้งบน Mac

```bash
.venv/bin/python -m pip install -r requirements-build.txt
.venv/bin/pyinstaller --noconfirm desktop.spec
```

ไฟล์ที่ได้คือ `dist/ChumkosoftScanner.app` ลากไปไว้ใน Applications แล้วเปิดตามปกติ บน Mac รุ่นที่ต้องขอสิทธิ์กล้อง คำขอจะแสดงในชื่อแอปนี้

### สร้างและติดตั้งบน Linux

รันคำสั่งสร้างแอปบน **เครื่อง Linux** (ไม่สามารถนำไฟล์ที่ build บน Mac ไปใช้บน Linux ได้):

```bash
.venv/bin/python -m pip install -r requirements-build.txt
.venv/bin/pyinstaller --noconfirm desktop.spec
bash install-linux.sh
```

จากนั้นเปิด **Chumkosoft Scanner** ในเมนู Applications ของผู้ใช้ปัจจุบัน ตัวแอปและข้อมูลอยู่ใน home ของผู้ใช้นั้น

## 2. คำสั่ง CLI สำหรับตรวจระบบและทดสอบโมเดล

ใช้กล้อง USB หรือกล้องใน Mac และอินเทอร์เน็ตเฉพาะตอนติดตั้ง/ตรวจเวอร์ชันโมเดล คำสั่งต่อไปนี้รันจากโฟลเดอร์ `offline_scanner`:

```bash
.venv/bin/python scanner.py update-models
```

คำสั่งนี้อ่าน `https://chumkosoft.com/models/scanner/manifest.json` และดาวน์โหลดเฉพาะไฟล์ที่ยังไม่มีหรือ SHA-256 ไม่ตรง เก็บใน `models/<รุ่น>/` จากนั้นจึงเปลี่ยน `models/active.json` แบบ atomic เมื่อไฟล์ครบและตรวจสอบผ่านเท่านั้น โปรแกรมตรวจ manifest ตอนเปิด `enroll` หรือ `scan` และใช้โมเดลในเครื่องตลอดการสแกน หากเว็บเข้าไม่ได้แต่มีไฟล์รุ่นเดิมครบ โปรแกรมจะใช้รุ่นเดิมต่อ หากไม่มีไฟล์ในเครื่อง จะบอกให้เชื่อมต่อเพื่อดาวน์โหลดก่อน

ไฟล์โมเดลรุ่นปัจจุบันอยู่ใน `public/models/scanner/v1` ของโปรเจกต์ ต้อง deploy เวอร์ชันนี้ขึ้นเว็บก่อน คำสั่ง `update-models` บนเครื่องอื่นจึงจะดาวน์โหลดได้ **การแก้โค้ดใน Mac ยังไม่ได้อัปเดตเว็บจริง**

เมื่อเปลี่ยนโมเดลที่สร้าง embedding คนละรูปแบบ ให้เปลี่ยน `embedding_version` ใน manifest ด้วย โปรแกรมจะใช้เฉพาะข้อมูลใบหน้าที่ลงทะเบียนด้วยเวอร์ชันนั้น และต้องลงทะเบียนภาพทดสอบใหม่ ข้อมูลเดิมไม่ถูกลบอัตโนมัติ

บน macOS อาจต้องให้สิทธิ์กล้องแก่ Terminal ใน System Settings → Privacy & Security → Camera. บน Linux ให้ตรวจ `/dev/video*` และสิทธิ์ผู้ใช้ต่อกล้อง

## 3. ลงทะเบียนภาพทดสอบผ่าน CLI (ทางเลือก)

เตรียมภาพของผู้สมัครใจ 1 คนต่อภาพ เห็นหน้าเดียวชัดเจน ภาพต้นฉบับไม่ได้ถูกคัดลอกเข้าฐานข้อมูล แต่ค่าจดจำใบหน้าถูกเก็บใน `data/scanner.sqlite3`:

```bash
.venv/bin/python scanner.py enroll test-001 "ผู้ทดสอบ 1" /path/to/consented-test-photo.jpg
.venv/bin/python scanner.py status
```

`data/` และ `models/` ของโปรแกรมถูก gitignore ข้อมูล `data/` บนเครื่องยังถือเป็นข้อมูลชีวมิติ ควรลบเมื่อจบการทดลอง ส่วนไฟล์ ONNX ใน `public/models/scanner/v1` เป็นโมเดลสาธารณะ ไม่ใช่ข้อมูลใบหน้าของนักเรียน

## 4. ทดสอบออฟไลน์ผ่าน CLI (ทางเลือก)

ปิด Wi-Fi หรือไม่เปิดเซิร์ฟเวอร์จำลอง แล้วรัน:

```bash
.venv/bin/python scanner.py scan --camera 0
```

เมื่อเห็นหน้าเดียวกัน 3 เฟรมต่อเนื่อง โปรแกรมจะเพิ่มรายการเช็กชื่อใน SQLite อย่างมาก 1 รายการต่อคนต่อวันตามเวลาไทย กด `q` เพื่อปิดหน้าต่างกล้อง แล้วตรวจคิว:

```bash
.venv/bin/python scanner.py status
```

การเห็นหน้า 3 เฟรมเป็นเพียงตัวกรองความนิ่ง **ไม่ใช่การพิสูจน์ว่ามีชีวิต** ยังสามารถถูกภาพถ่าย/วิดีโอหลอกได้

## 5. ทดสอบการส่งเมื่อกลับมาออนไลน์

เปิดอีก Terminal (ในโฟลเดอร์เดียวกัน):

```bash
.venv/bin/python mock_server.py
```

Terminal แรก:

```bash
.venv/bin/python scanner.py sync http://127.0.0.1:8765/events
.venv/bin/python scanner.py status
```

หรือขณะเปิดแอป ใช้ `.venv/bin/python desktop_app.py --sync-url http://127.0.0.1:8765/events` โปรแกรมจะลองส่งทุก 15 วินาที หากส่งไม่สำเร็จ คิวจะยังคงอยู่ เซิร์ฟเวอร์จำลองบันทึก `event_id` ซ้ำเพียงครั้งเดียวใน `data/mock.sqlite3`

## ส่วนที่ยังไม่เชื่อมกับเว็บจริง

การอัปโหลดรูปมี API แล้ว แต่การดึงค่าจดจำใบหน้าจากเว็บลงเครื่องอื่นและการส่งรายการเช็กชื่อย้อนหลังยังไม่มี ต้องเพิ่ม API แบบ batch สำหรับอุปกรณ์สแกน ตรวจสิทธิ์/ความยินยอมและภาคเรียนอีกครั้ง รับเวลาที่สแกนพร้อมตรวจความคลาดเคลื่อนนาฬิกา รับ `event_id` ซ้ำอย่างปลอดภัย ตอบรับรายรายการ ทำ audit และส่ง LINE เพียงครั้งเดียว ควรกำหนดอายุสูงสุดของข้อมูลใบหน้าที่ cache และวิธีเพิกถอนข้อมูลใบหน้าบนอุปกรณ์ ขณะนี้ `confirmCheckInAction` ของเว็บรับแค่ `studentId` และบันทึกเวลาปัจจุบัน จึงใช้กับการซิงก์ย้อนหลังไม่ได้

ทดสอบตรรกะคิวโดยไม่ต้องติดตั้ง OpenCV: `python -m unittest -v test_offline.py`
